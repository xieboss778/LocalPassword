# LocalPass 界面原型 · Bitwarden 原生布局

按上游 Bitwarden 客户端的布局与组件语言重做的 LocalPass 界面原型。覆盖**扩展弹窗（380×620）**、**桌面端（1160×760）**与**网页内联自动填充（1160×760）**，数据全部为假，没有任何加密、存储或网络逻辑。

这是设计稿，不是产品代码；不要把它接进 `apps/` 或 `libs/`。

## 打开

直接双击 `index.html`，或在目录里起一个静态服务器：

```bash
cd design-system/legacy/prototypes/ui-redo-d
python3 -m http.server 4173
# http://localhost:4173
```

页面是自包含的：本地 Inter / BWI 字体、生成好的 `bwi.css`，不会发出任何网络请求。

可用 URL 参数直达某个界面：

```
?device=popup|desktop|inline
&screen=<p-*|d-*|w-*>  例如 p-vault、d-item、w-inline-login
&item=<条目 id>        例如 github、bank、ssh
&type=<表单类型>       例如 login、card、sshkey
&mode=edit|new         p-form 直接打开时的编辑 / 新建模式
```

## 覆盖范围

共 **73 个索引项**、**58 个界面函数**（弹窗 27 / 桌面 27 / 网页内联 4），另有 5 条关键流程（① 建库、② 解锁并复制、③ 桌面列表→详情→编辑、④ 生成密码、⑤ 备份→恢复）。

### 扩展弹窗（41）

- **解锁与首次使用**：解锁、输错等待（不登出）、首次设置、安全密钥解锁
- **保险库**：分组列表、空状态
- **条目**：8 种类型的详情（登录 / 卡片 / 令牌 / SSH 私钥 / 服务器 / 许可证 / 身份 / 笔记）、操作单、动态口令二维码、通行密钥与自定义字段展示
- **新建与编辑**：8 类类型选择 + 8 种表单；登录表单按项目 / 登录信息 / 自动填充 / 附加选项分组，含自定义字段编辑器与通行密钥删除
- **工具**：生成器、生成历史
- **设置与组织**：设置、安全设置、外观、文件夹、回收站、关于
- **备份与数据**：云备份、存储配置、从备份恢复、导入、导入预览、导出、网络闸门、数据与安全

### 网页内联（4）

- **登录**：同一域名 3 个账户，输入用户名过滤，通行密钥 / 密码分组，最近使用优先
- **通行密钥**：条件式提示、选择账户、验证中与取消
- **验证码**：验证码字段内联选择，多账户实时口令与倒计时
- **自动填充**：填充确认卡、剩余秒数、自动复制、切换账户

### 桌面端（28）

- **解锁**：解锁、安全密钥解锁、首次设置
- **保险库**：表格 + 文件夹卡片、空状态、详情抽屉（登录 / 卡片）、编辑抽屉、新建、删除确认、回收站、文件夹
- **工具**：生成器、生成历史、导入、导入预览、导出
- **备份**：云备份、存储配置、从备份恢复
- **设置**：安全、保险库、外观、备份、关于、网络闸门、数据与安全

## 网页内联的设计取舍

同一域名存在多个账户时，建议列表以**账户**为第一信息，而不是按条目名平铺：

1. **账户优先**：主标题是用户名，副标题是账户标签 + 可用方式（通行密钥 / 密码 + 验证码）。同一账户同时有通行密钥和密码时，会在两个分组各出现一次，因为用户此刻的意图不同。
2. **方法分组**：通行密钥在“通行密钥”分组，密码在“密码”分组；每组带数量，最近使用的账户排在最前，并标“上次使用 / 当前账户”。
3. **一个活动行**：任意时刻只有一行高亮，键盘焦点与鼠标悬停共用同一套高亮；产品实现时补 `↑↓` 移动、`Enter` 执行、`Esc` 关闭。
4. **输入即过滤**：在用户名字段输入会实时过滤账户；无匹配时给出“清除筛选 / 新建条目”，不把空列表丢给用户。
5. **通行密钥按需出现**：只有网站发起 WebAuthn 条件式请求且本地有绑定凭据时才显示；选择后进入验证中状态，可取消，不把通行密钥混进普通密码建议。
6. **验证码不猜账户**：TOTP 内联只出现在验证码字段；自动填充优先绑定上一步刚选的账户，但菜单仍列出全部可用账户并支持“切换账户”。
7. **填充后可回退**：密码填充后收成小胶囊，TOTP 填充后保留确认卡（代码、剩余秒数、复制、切换账户），不阻断页面自身操作。
8. **无障碍**：可见焦点环、`autocomplete="one-time-code"`、粘贴友好、不只依赖 hover；填充动作有 toast 反馈。

cd design-system/legacy/prototypes/ui-redo-d

## 重写进产品的路径

原型只作为视觉与交互参考。真正落地时：

1. 以现有 `apps/desktop` 的 VFO1 布局、`apps/browser` 弹窗骨架、`libs/angular` 与 `libs/components` 组件为基座，不新增平行组件。
2. 先按屏对照表把每个原型屏映射到现有组件（vault、drawer、generator、backup、settings、trash）；缺的槽位用 `tw-` 前缀的语义令牌补齐。
3. 网页内联落在 `apps/browser/src/autofill/` 现有的 content script / inline-menu Lit 组件与 `overlay.background.ts` 数据流上，不把 Angular 组件塞进内容脚本。
4. 新增持久化状态时注册到对应 `state-definitions.ts`；不把原型里的假数据、文案、内联样式带进产品代码。
5. 加密与存储仍走本地保险库服务；不新增加密逻辑，不在日志 / 错误 / 存储里出现明文。
6. 涉及加密、同步、本地写入的改动必须补单测，并实际构建扩展验证。

## 边界

- 不新增 `upstream` remote，不拉取、合并或对照同步官方 Bitwarden 代码；所有网络操作只针对 `origin`。
