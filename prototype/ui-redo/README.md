# 界面重构原型（临时）

三种结构性不同的界面方向，针对 LocalPassword 扩展弹窗（380 × 620）。

- 同一份假数据，三个方向：**A 卡片流** / **B 命令面板** / **C 分组原生**
- 切换：底部黑色药丸点箭头，或键盘 `←` `→`（`1` `2` `3` 直达），或用 URL `?variant=A|B|C`
- 四个界面：解锁 / 保险库 / 条目详情 / 设置·备份（顶部灰条切换，不属于设计本身）

## 怎么看

直接双击 `index.html`，不需要构建、不需要依赖。

## 为什么是独立 HTML 而不是应用里的路由

`/prototype/UI.md` 优先「嵌进真实页面」（sub-shape A），但那要求每次改版都重新构建扩展并在 Chrome 里重载。
这一轮要反复比结构，所以退到 sub-shape B：单文件、零依赖、随手刷新。

拍板之后：选中的方向按 `angular-modernization` + `writing-client-code` 重写进 `libs/angular` 与 `apps/browser`，
这个目录整体丢弃（原型只作为决策存档）。

## 三个方向的结构差异（不是换配色）

| | A 卡片流 | B 命令面板 | C 分组原生 |
| --- | --- | --- | --- |
| 主导航 | 单列 + 悬浮新建键 | 顶部输入即命令，键盘驱动 | 底部 4 个 Tab |
| 信息密度 | 低（每屏 3–4 条） | 高（9–10 条，含分值/快捷键） | 中（分组列表） |
| 主操作 | 大号主按钮 | 回车 / 快捷键 | 行内开关与 chevron |
| 设置呈现 | 卡片列表 | `:config` 命令式条目 | iOS 分组 + 开关 |
| 适合 | 鼠标为主的普通用户 | 键盘重度用户 / 开发者 | 桌面端原生感 |
