# 安装、备份与恢复

LocalPass 只有两个客户端：Chrome 扩展与桌面端（Electron）。两者都完全离线可用，
共用同一套 `account.json` 与快照格式；授权 Cloudflare R2（或任意 S3 兼容存储）后可以跨设备同步。

## 一、安装扩展（Chrome / Edge）

1. 打开 `chrome://extensions`，打开右上角「开发者模式」。
2. 点「加载已解压的扩展程序」，选择 CI 产物 `localpass-chrome` 解压出来的目录（含 `manifest.json`）。
3. 固定到工具栏。扩展 ID 固定为 `gmobddgobjdhbjhedhgaeekhgchkoncm`（由 manifest 的 `key` 决定），
   重装后 ID 不变，因此本机数据与安全密钥登记都不会丢。

> Chrome 官方限制：外部安装的扩展更新地址必须指向应用商店，所以本产品不提供自动更新。
> 升级时用新产物覆盖同一目录，然后在扩展页点「重新加载」；数据不受影响。

## 二、安装桌面端

CI 产出未签名安装包，首次安装会被系统拦一下：

| 平台    | 产物                                | 首次打开                                                  |
| ------- | ----------------------------------- | --------------------------------------------------------- |
| Windows | `LocalPass-Setup-x.y.z.exe`（NSIS） | SmartScreen 提示时点「更多信息 → 仍要运行」               |
| macOS   | `LocalPass-x.y.z.dmg`               | 右键应用 → 打开；或「系统设置 → 隐私与安全性 → 仍要打开」 |
| Linux   | `AppImage`                          | `chmod +x` 后直接运行                                     |

桌面端数据在 `<userData>/data.json`（权限 0600），旁边保留一份 `data.json.bak`。
覆盖安装不会清数据；卸载会清。

## 三、第一次使用

1. 打开扩展（或桌面端），起始页有三个入口：**创建本地保险库** / **从备份文件恢复** / **从云存储恢复**。
2. 创建时填一个邮箱（只作标识与 KDF 盐）与主密码。**主密码无法找回**——没有服务器，也没有找回邮件。
3. 创建完成后直接进入保险库：新增、编辑、文件夹、回收站、自动填充、Passkey 全部可用，
   付费功能（TOTP、附件、安全密钥）默认全开。

## 四、配置云备份（可选）

1. Cloudflare 控制台 → R2 → 创建一个桶，例如 `localpass`。
2. 创建 R2 API 令牌：权限选「对象读与写」，范围限定到这**一个桶**。
3. 给桶加 CORS 规则（**桌面端必需**）：R2 桶 → Settings → CORS Policy →
   Edit，粘贴下面这条并保存。桌面端在渲染进程里直接请求 R2，会经过浏览器的跨域检查；
   扩展有 `*://*/*` 主机权限，不受这条限制，但加了不影响扩展。

   ```json
   [
     {
       "AllowedOrigins": ["*"],
       "AllowedMethods": ["GET", "PUT", "HEAD", "DELETE"],
       "AllowedHeaders": ["*"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```

4. 扩展：设置 → 云备份；桌面：侧栏 → 云备份。填入：
   - 端点：`https://<账户ID>.r2.cloudflarestorage.com`
   - 区域：`auto`（R2）；其他 S3 兼容存储填各自区域
   - 桶名、Access Key ID、Secret Access Key
5. 点「测试连接」，成功再点「保存」。

桶就是保险库的边界：**一个桶只放一座保险库**，两个账号请用两个桶。所有对象都在桶根，
没有前缀，也没有按账号分的目录：

```
<桶>/account.json                       账号身份与解锁材料，恢复的锚点
<桶>/manifest.json                      指向最新快照（并发冲突靠它的 ETag）
<桶>/snapshots/<时间戳>.json             「同步」写入的加密状态
<桶>/exports/<年-月-日>/<时间戳>.json    「导出备份」写入的标准 JSON
```

保存后（全部手动，没有后台定时器）：

- 点「同步」：推送本机快照、拉取远端更新。首次上传会先写 `account.json`。
- 点「导出备份」：生成一份带独立「备份口令」的标准 JSON；这一步同样会保证 `account.json` 存在。
- 两类历史各保留最近 10 份，每次上传成功后自动清理；清单当前指向的快照永远不会被删除。
- 上传前会检查桶的归属：桶里已有另一座保险库的 `account.json` 时拒绝写入，不会覆盖对方。

## 五、备份口令

「云备份」页的**备份口令**只在导入导出文件时需要：

- 每个账号只在首次使用时随机生成，用你的用户密钥加密后保存在本机，页面上可查看、可复制。
- 任何 LocalPass 兼容客户端导入备份文件时都要用它。**请单独保存**（例如写在纸上放进抽屉）。
- 换了设备、本机数据丢了，只要桶里的 `account.json` 与 `snapshots/` 还在，用主密码就能恢复；
  如果只剩 `exports/`，用「主密码 + 备份口令」导入。

## 六、恢复

- **从备份文件**：起始页 → 从备份文件恢复 → 先建一个空保险库 → 自动跳到导入页 → 选备份文件 → 输入备份口令。
- **从云存储**：起始页 → 从云存储恢复 → 填端点、桶、Access Key、Secret 与主密码（没有前缀字段）。
  向导直接读取桶根的 `account.json`，复用其中的账号标识（`userId`）重建账号，再拉取快照。
  所以恢复出的设备与写备份的设备是**同一个账号**：共享解锁能对上，之后的同步也写同一个桶。
  如果桶里只有 `account.json` 和 `exports/`（只点过「导出备份」），恢复出的是空库，
  去导入页选那份导出并输入备份口令。
- **不要**先新建空保险库再配置同一个桶：新建会生成新的账号标识，上传前的归属检查会发现桶属于另一座库并拒绝写入。
  正确做法是走「从云存储恢复」。

## 七、安全说明

- 数据只在本机与你自己配置的桶里。除你手动点「检查泄露」外，应用不会向外发任何请求；
  钓鱼站点列表下载、网站图标拉取、密码泄露自动检查三项默认关闭。
- 网络闸门在 `ApiService` 层拦截：非白名单请求直接抛错，不会被当成 401/403 而触发登出。
- 连续输错 PIN 不会销毁保险库，只会递增等待。
- 登出等于删除本机数据（没有服务器副本），确认框会提示先导出。
