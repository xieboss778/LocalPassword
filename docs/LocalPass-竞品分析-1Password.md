# LocalPass × 1Password 竞品分析

> 分析日期：2026-11-27
> 对比对象：LocalPass（仓库 `main`，Chrome/Edge 扩展 + 桌面端）｜1Password for Mac 8.12.46 + 1Password in the browser 8.12.46.29（本机已安装）
> 关注面：效率提升、用户体验、产品细节、用户反馈打磨
> 约束：只读分析，未修改任何产品代码，未登录或读取本机 1Password 保险库内容

---

## 0. 结论先行

### 五条判断

1. **功能覆盖面不是主要差距，"取用速度"才是。**
   LocalPass 的本地保险库、8 类条目、TOTP、Passkey、加密备份、R2/S3 快照都已可用；但从"想到一条密码"到"它在剪贴板里"，1Password 约 4 个动作、0 次窗口切换，LocalPass 约 6–7 个动作、2 次焦点切换，而且每次打开弹窗都要重新输入搜索词。

2. **"看"已经做到八成，"用"的密度不够。**
   弹窗 27 屏、内联 4 屏、桌面 27 屏已按原型对齐，空态、分组、详情、内联菜单都在。但 1Password 有 20+ 个可用快捷键（列表方向键、字段复制、编辑、新建、归档），LocalPass 扩展只注册了 4 个命令、3 个默认快捷键，列表甚至不能用方向键移动。

3. **最刺痛的不是缺功能，是"已有能力没有入口"。**
   条目历史、归档、密码健康、1Password 1PUX/1PIF/CSV 导入、CSV 导出、剪贴板清除设置——代码里都有，产品里走不到。这是典型的"最后一公里"问题，成本最低、收益最高。

4. **数据可信度有三个洞：导入不去重、删除无就地撤销、修改无历史。**
   1Password 用"归档 + 历史版本 + 恢复"三件套解决；LocalPass 三件都缺，用户改错一次密码就永久丢上一版。

5. **离线是护城河，天花板用"本地等价物 + 自备桶"抬高，而不是回云。**
   1Password 的强项分两类：一类能离线成立（条目历史、归档、体检、分享包、桌面填充），做本地实现；一类必须服务端（团队权限、SSO、托管恢复），明确不做或降级为"共享桶 + 同级共享"。多设备同步不放弃——落到 Cloudflare R2 的端到端加密镜像上，桶是可替换的哑存储，不引入账号、服务端或遥测。**不要按 1Password 的功能清单逐项对齐**，要按"离线用户每天真正会遇到的摩擦"排序。

### 三个最该先做的事

| 顺序 | 动作                                                                                         | 为什么是它                                                       |
| ---- | -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 1    | **搜索 + 全局唤起（Quick Search）**：先把索引扩到全字段，再包一层快捷键唤起，回车即复制/填充 | 直接消灭最大的一处效率差；先修索引可避免全局入口建在错误的检索上 |
| 2    | **把已有能力接出来**：条目历史、归档、1PUX/CSV 导入、CSV 导出、搜索覆盖备注与 URL            | 代码已存在，主要是 UI 入口与映射；同时补齐"可迁移、可回滚"的信任 |
| 3    | **键盘与反馈打磨**：列表方向键与快捷键、toast 可读可撤销、复制后状态可见                     | 高频、低成本，决定"专业感"与"敢不敢每天用"                       |

> 多端同步不在这一批里，但方向已定：**R2 端到端加密镜像 + 自动同步（可关，设计未实施）**。
> 它不是"上云"，是"把桶当会 412 的硬盘"。当前产品仍是手动同步；规格、缺口与验收见
> `docs/LocalPass-离线优先与R2同步设计.md`。

## 1. 方法与边界

| 维度           | 做法                                                                | 边界                                           |
| -------------- | ------------------------------------------------------------------- | ---------------------------------------------- |
| LocalPass 实现 | 只读检索源码、路由、清单、QA 记录与文档                             | 未构建、未运行、未修改                         |
| 本机 1Password | 读取 `Info.plist`、扩展 `manifest.json`、安装体积；观察权限与快捷键 | 未登录，未读取任何保险库条目                   |
| 1Password 行为 | 官方 release notes / support 文档 / 社区帖 / 第三方评测             | 部分交互引用官方文档，非逐项实机点击           |
| 量化           | 按界面结构估算动作数与耗时，标注"估算"                              | 未做可用性实验，绝对秒数仅供排序，不作验收指标 |

**结论的可信度分级**：代码与清单类结论为"可复现事实"；动作数/耗时为"结构化估算"；用户口碑为"公开样本，非统计抽样"。

## 2. 定位差异：复杂度放在哪一端

| 维度     | 1Password 8                                       | LocalPass                                          |
| -------- | ------------------------------------------------- | -------------------------------------------------- |
| 信任模型 | 零知识 + Secret Key + 托管云                      | 零知识 + 纯本地文件，无账户、无服务端              |
| 数据位置 | 厂商服务器（1P8 起取消本地库同步）                | 浏览器本地存储 / 桌面 `data.json`                  |
| 成本     | 订阅制，无永久免费层（约 $2.99–3.99/月）          | 全部功能免费                                       |
| 上手     | 注册 → 订阅 → 保存 Emergency Kit → 装扩展         | 建库（邮箱可选 + 主密码）即用                      |
| 跨端     | 自动同步、多设备、家庭/团队                       | 端到端加密镜像到自备 R2/S3，自动同步可关、可换目标 |
| 协作     | 共享库、限时链接、权限、SSO                       | 加密分享包 + 共享桶（同级共享，无权限分级）        |
| 可迁移   | 导入数十种来源（含 1PUX/1PIF/CSV），导出 1PUX/CSV | 导入 3 个入口（实际仅 JSON），导出加密/明文 JSON   |
| 可审计   | 闭源客户端 + 第三方审计报告                       | 自有代码 + GPL 上游内核，可自行验证网络闸门        |
| 故障半径 | 厂商故障/封号/订阅过期 → 只读或不可用             | 本机故障 → 从自备桶重建；桶故障 → 本机仍是完整副本 |

**一句话**：1Password 把复杂度放在服务端（同步、恢复、分享、合规），LocalPass 把复杂度放回客户端（备份、迁移、多端）。所以 LocalPass 的体验债不是"少几个功能"，而是——**服务端原本替用户做的琐事，现在交回给用户，却没有配对应的工具**。多端这一项正在用 R2 镜像抵消：桶由用户自备，但同步、合并、冲突、恢复由产品做掉——复杂度留在客户端，而不是交给一家公司。

## 4. 关键体验差异（按"每天会痛几次"排序）

### D1. 取用路径：Spotlight 式唤起 vs 打开弹窗再找

- **1Password**：`⌘⇧Space` 唤起 Quick Access，输入两三个字母，`⇧⌘C` 复制密码，全程不离开当前窗口；它还会按当前前台应用/网站推荐条目。
- **LocalPass**：`Ctrl+Shift+Y` 打开 380×620 弹窗 → 点搜索框 → 输入 → 点条目 → 点复制 → 关闭。弹窗每次重建，搜索词不保留。
- **差距**：不是"少一个快捷键"，而是**打断了当前任务**。复制密码本应是 3 秒的肌肉记忆，现在是一次上下文切换。
- **证据**：1Password Quick Access 文档；LocalPass `manifest.v3.json` 仅注册 `_execute_action`/`autofill_login`/`generate_password`/`lock_vault`。

### D2. 键盘密度：20+ 快捷键 vs 3 个默认键位

- 1Password：`⌘C` 复制用户名、`⇧⌘C` 复制密码、`⌥⌘C` 复制验证码、`⇧⌘F` 打开网站并填充、`⌘E` 编辑、`⌘N` 新建、`Delete` 归档、`⌘Delete` 删除、`⌘F` 搜索、`⌘1..9` 切账户/收藏集。
- LocalPass：弹窗内几乎没有全局键位；列表行是 `tabindex=0` 的普通元素，不能 ↑↓ 移动，也不能 `⌘C` 复制当前行。
- **差距**：重度用户的手会"离开键盘去找鼠标"，这是留存问题，不是效率小数点。

### D3. 搜索：四个字段 vs 全字段 + 语法

- LocalPass 的 `visible()` 只拼 `name / subtitle / folderName / username`（`vault-list-v2.component.ts:329-352`）。
- 结果：**搜备注、搜 URL、搜自定义字段、搜卡号后四位都搜不到**。用户的记忆往往是"那个用来注册 ChatGPT 的邮箱"或"备注里写了备用码"，恰恰不在索引里。
- 1Password 搜索覆盖标题、分区、字段、备注、标签、类别、保险库，并支持引号精确匹配和 `=` 过滤器。
- **差距**：库越大，越依赖搜索；LocalPass 的搜索在 50 条以内够用，500 条以上会迅速失效。

### D4. 填充覆盖：网页三类 vs 全场景

- 1Password：网页登录/银行卡/身份都在内联菜单；macOS 上还能 `⌘\` 直接填桌面应用和系统弹窗。
- LocalPass：内联菜单只有登录、通行密钥、TOTP；银行卡/身份要走右键菜单或快捷键；桌面应用完全无解。
- **差距**：LocalPass 的"离线"卖点本应覆盖"不联网的本地应用"（IDE、数据库客户端、内网后台），但恰恰在这些场景缺席。

### D5. 数据可回溯：改错就没了 vs 版本可回滚

- 1Password：密码字段可看历史并复制旧值；整条可看历史版本并 Restore；误删先归档。
- LocalPass：改密码直接覆盖；删除只能去回收站；`vault-password-history` 组件存在但 V2 详情页没有入口。
- **差距**：这是**信任**问题。用户敢不敢在 LocalPass 里改银行密码，取决于改错了能不能回去。

### D6. 规模化管理：文件夹 + 逐条 vs 标签 + 批量

- 1Password：标签、收藏、多选、批量移动/删除/归档。
- LocalPass：只有文件夹和收藏，删除/移动/编辑都要逐条。
- **差距**：导入 200 条后第一次整理，就是用户体验的"劝退时刻"。QA 已记录"重复导入不会自动跳过"，会放大这个问题。

### D7. 迁移摩擦：数十种来源 vs 一个 JSON

- LocalPass 的"导入"页有三张卡，但两张（LocalPass 备份 / Bitwarden 导出）都调用同一个 `importType: "localpassjson"`，文件选择器 `accept=".json"`。
- 上游 `libs/importer` 已注册 1PUX、1PIF、1P Mac/Win CSV，却没有任何入口能选中 `.1pux` / `.csv`。
- **差距**：一个 1Password 用户想试用 LocalPass，第一步就卡住。这直接掐断了最大的竞品转化来源。

### D8. 反馈闭环：每条 release note 都在修体验 vs 没有渠道

- 1Password 的更新日志里大量是这类条目：通知常驻到手动关闭、占位符改为"Enter a title"、网址下划线提高对比度、屏幕阅读器播报任务完成、把"Save login"改成问句。
- LocalPass：没有应用内更新日志、没有问题反馈入口、没有诊断包；离线定位下也没有遥测。
- **差距**：不是"少一个页面"，而是**产品失去了听见用户的能力**。离线产品更需要"用户主动交回信息"的低摩擦通道。

### D9. 视觉识别：站点图标 vs 类型色块

- 1Password 用站点富图标 + 品牌色，扫一眼就能定位；LocalPass 用类型色块 + 首字母，同类条目（多个登录）在列表里长得一样。
- **差距**：列表扫描速度。离线不能依赖 favicon 服务，需要本地图标缓存/内置图标包/用户自定义图标。

## 5. 效率量化（估算，仅用于排序）

### 5.1 三个时钟

| 阶段                         | 1Password                                        | LocalPass                                        | 谁更好        |
| ---------------------------- | ------------------------------------------------ | ------------------------------------------------ | ------------- |
| 首次上手（到第一条密码可用） | 3–5 分钟（注册、订阅、存 Emergency Kit、装扩展） | 30–60 秒（建库即用）                             | **LocalPass** |
| 单次取用（复制/填充一条）    | 3–5 秒，0 次窗口切换                             | 8–12 秒，2 次焦点切换                            | **1Password** |
| 长期维护（备份、迁移、体检） | 自动同步 + Watchtower                            | 手动备份 + 手动同步 + 无体检（自动同步在批次 A） | **1Password** |

**解读**：LocalPass 赢在"开始"，输在"每天"和"长期"。而"每天"的体验决定留存，"长期"的体验决定信任。

### 5.2 典型任务动作数

| 任务                      | 1Password             | LocalPass             | 差距来源                             |
| ------------------------- | --------------------- | --------------------- | ------------------------------------ |
| 复制当前站点密码          | 4 个动作 / ~4s        | 6–7 个动作 / ~10s     | 无全局检索、无字段快捷键、搜索不记忆 |
| 登录桌面应用              | 1 个快捷键 / ~2s      | 无法直接完成 / 15–25s | 无 Universal Autofill                |
| 按备注/URL 找条目         | 2 个动作 / ~4s        | 无法直接完成 / 30s+   | 搜索不覆盖备注与 URL                 |
| 批量整理 50 条导入数据    | 多选 + 批量 / ~3min   | 逐条 / ~40min         | 无多选、无批量、无标签               |
| 从 1Password 迁移 1000 条 | —（反向）             | 不可用                | 导入收窄到 `.json`                   |
| 改错后回滚                | 3 个动作 / ~5s        | 不可能                | 无历史版本入口                       |
| 安全体检                  | 打开 Watchtower / ~2s | 无入口                | health 模块未接                      |

> 假设：每天取用 6 次、每月整理 1 次、每年迁移 1 次。据此，单次取用一年约多花 3–4 小时；批量整理一年约多花 7 小时；迁移则直接失败。**时间不是主要成本，"放弃使用"才是。**

### 5.3 摩擦热力图（按频次 × 痛感）

| 频次 \ 痛感 | 高                         | 中                 | 低       |
| ----------- | -------------------------- | ------------------ | -------- |
| 每天多次    | 取用路径、键盘、搜索       | 复制反馈、自动锁定 | 视觉图标 |
| 每周        | 保存/更新提示、内联卡/身份 | 批量操作、标签     | 多语言   |
| 每月/一次性 | 迁移、恢复、历史回滚       | 备份验证           | 关于页   |

## 8. 具体改进建议（规格级）

> 以下建议不新增加密逻辑；唯一的例外是同步所需的设备签名（Ed25519，见同步设计 S8）。涉及密钥、PRF、分享包封装格式的改动，按 `AGENTS.md` 先报 owner 评审。

### 8.1 Quick Search：一个快捷键解决"取用"

**现状**：只能开弹窗；弹窗重建后搜索词丢失。
**目标**：任意页面/任意应用前台，`Ctrl/Cmd+Shift+Space` 唤起一个 480×420 的无边框搜索窗，输入即出结果，`↑↓` 选择，`Enter` 填充/打开，`⌘C` 复制用户名，`⇧⌘C` 复制密码，`⌥⌘C` 复制验证码，`Esc` 关闭。

**做法**：

- 扩展：新增 `quick_search` 命令，`chrome.windows.create({type:"popup", width:480, height:420})` 打开独立路由；复用 `VaultPopupItemsService`，不新建数据通道。
- 桌面：`globalShortcut.register` + 无边框 `BrowserWindow`；复用同一套检索函数与行组件。
- 排序：当前标签页 URL 匹配 > 最近使用 > 收藏 > 修改时间。
- 空态：显示"最近使用"与"收藏"两组，而不是空白。

**落点**：`apps/browser/src/manifest.v3.json`（commands）、新路由 + `libs/angular/src/local-ui/quick-search`、`apps/desktop/src/main/main.ts`（globalShortcut）、`libs/vault/src/utils/search.ts`（纯函数）。
**验收**：从任意页面到密码进剪贴板 ≤ 3 个动作；无鼠标可完成；检索 1000 条库 P95 < 150ms。

### 8.2 搜索升级：先让索引覆盖"用户真正记得的东西"

**现状**：只搜 4 个字段。
**目标**：覆盖名称、用户名、URL/URI、备注、自定义字段标签与值、文件夹名、卡号后四位；支持引号精确匹配；支持 `=type:` `=folder:` `=favorite:` `=has-totp:`；输入为空时展示"最近使用 / 收藏"。

**做法**：

- 抽出纯函数 `searchCiphers(ciphers, query)`，返回命中字段与高亮区间；列表与 Quick Search 共用。
- 结果行显示"命中位置"（如 `备注：备用码 882…`），让用户知道为什么命中。
- 最近使用：内存 + 本地状态，上限 20 条，锁定后不清空；提供"清除最近记录"。

**落点**：`vault-list-v2.component.ts`、`libs/vault/src/utils/search.ts`、`libs/state/src/core/state-definitions.ts`（新增 recent 状态）。
**验收**：备注/URL/自定义字段查询命中率 100%；搜索结果排序稳定；有单测覆盖中文分词与大小写。

### 8.3 键盘体系：让手不离开键盘

**现状**：列表不可方向键导航；无字段复制快捷键。
**目标**：

- 列表：`↑↓` 移动焦点、`Enter` 打开、`⌘C` 复制用户名、`⇧⌘C` 复制密码、`⌥⌘C` 复制 TOTP、`⌘E` 编辑、`Delete` 归档、`⌘Delete` 删除、`/` 聚焦搜索、`Esc` 清空。
- 全局：`⌘F` 搜索、`⌘N` 新建、`⌘,` 设置、`⇧⌘L` 锁定。
- 所有快捷键在"设置 → 快捷键"可查、可改；冲突时提示。

**做法**：列表改用 roving tabindex + `role="listbox"/"option"`，抽 `VaultKeymapService` 统一分发；扩展用 `commands` 注册全局键，桌面用菜单 accelerator + `before-input-event`。
**落点**：`vault-list-v2.component.ts`、新建 `libs/angular/src/local-ui/keymap.service.ts`、桌面 `menu.*.ts`。
**验收**：5 个核心任务可全程无鼠标完成；键盘焦点始终可见；屏幕阅读器能播报行内容与操作结果。

### 8.4 条目历史与归档：把"后悔药"接出来

**现状**：`vault-password-history` 与 `CipherArchiveService` 都在，V2 无入口。
**目标**：

- 详情页密码行尾部 `⋯` → "查看历史"，展示时间、旧值、复制；受重提示保护的条目先验主密码。
- 详情操作单新增"归档"；设置页新增"归档"行（计数）；归档条目不参与搜索默认结果，可筛选查看。
- 归档与删除的文案明确区分："归档＝收起来，不算删除"。

**落点**：`item-view-v2.component.ts`（操作单）、`settings-list-v2.component.ts`（归档行）、`apps/browser/src/vault/popup/settings/archive.component.ts`（复用）、`CipherService` 本地分支确认 `archivedDate` 落盘。
**验收**：改密码后可看到并复制上一版；归档后列表/搜索行为符合定义；可随时取消归档；删除条目 30 天内可恢复；有 E2E 覆盖。

### 8.5 迁移：把已经写好的导入器放出来

**现状**：三张卡、两个走同一 JSON 解析、`accept=".json"`。
**目标**：

- 导入来源扩为：LocalPass 备份、Bitwarden（加密/明文 JSON）、**1Password（.1pux/.1pif/.csv）**、通用 CSV、Google Authenticator。
- 文件选择器按来源设置 `accept`；拖拽区按扩展名自动识别来源。
- 预览页显示：将导入 / 重复跳过 / 无法识别，并允许"覆盖或跳过"选择。
- 去重键：`name + username + 主 URI`；同键条目默认跳过，可在预览里改为覆盖。

**落点**：`import-source-v2.component.ts`、`import-preview-v2.component.ts`、`libs/importer/src/services/import.service.ts`（已注册 1PUX/1PIF/CSV）、预览暂存服务。
**验收**：1000 条 1PUX 导入成功率 ≥ 99%，字段保真（TOTP、备注、自定义字段、文件夹）；重复导入 0 新增；失败条目有逐条原因。

### 8.6 导出：给出"能带走"的格式

**现状**：加密 JSON / 明文 JSON；服务层支持 CSV。
**目标**：导出页增加 CSV（以及后续 1PUX），必须二次验证主密码 + 明确风险提示 + 默认文件名带日期；导出后 toast 提供"打开所在文件夹"。
**落点**：`export-browser-v2.component.ts:53-56`、`individual-vault-export.service.ts:60`。
**验收**：CSV 可被 1Password/Bitwarden/Chrome 导入；导出前必须重新验证；审计日志/诊断信息不含明文。

### 8.7 保存与更新：把"最后一秒"做顺

**目标**：

- 注册/改密后，通知条用问句文案（"保存到 LocalPass？"），提供"保存 / 更新已有条目 / 忽略"。
- 更新时按 `URI + username` 匹配，命中多条时让用户选，不静默新建。
- 同一站点可"不再提示"，设置里可恢复。
- 保存成功后 1.5s 内可在弹窗里看到新条目（列表乐观更新）。

**落点**：`apps/browser/src/autofill/notification/*`、`overlay.background.ts`、`cipher.service.ts` 本地写入分支。
**验收**：注册→保存→回填闭环 0 失败；重复条目率 < 1%；文案 en/zh_CN 成对。

### 8.8 内联菜单扩展：银行卡与身份

**目标**：在检测到卡号/有效期/地址字段时，内联菜单增加"银行卡 / 身份"分组；支持设置默认卡与默认身份；卡号默认掩码显示，选择后填充并提示"已填尾号 8891"。
**落点**：`apps/browser/src/autofill/content/components/inline-menu/*`、`overlay.background.ts`（数据组装）、设置页"自动填充"。
**验收**：结账页可 2 步完成卡信息填充；默认项生效；不引入新的网络请求。

### 8.9 安全体检：离线规则 + 可选联网

**目标**：新增"安全检查"页：

- 本地规则（无需联网）：弱密码（长度/字符集/常见词）、重复使用、超过 365 天未改、有 URI 但无 TOTP、有 Passkey 可用标记的站点清单（来自本地条目字段）。
- 泄露查询：默认关闭；开启时明确说明"将向 X 发送密码前缀"，并走网络闸门白名单；也可导入离线泄露清单。
- 每条问题提供"去修改"直达编辑页，改完自动从清单移除。

**落点**：`apps/browser/src/dirt/health/*`（已有组件）、`libs/angular/src/tools/settings`（入口）、网络闸门白名单配置。
**验收**：离线全功能可用；泄露查询可完全关闭；问题条目数随修改实时下降。

### 8.10 反馈闭环：离线产品的"听得见"

**目标**：

- "关于 → 生成诊断信息"：版本、平台、条目计数、最近 50 条错误码、功能开关；**绝不含条目内容、URL、用户名、密码**；一键复制，用户自行粘贴到 issue。
- 应用内"更新日志"页，按版本列出修复与已知问题。
- "已知限制"页（Passkey 需真机、macOS 打包、无自动更新）。
- 设置里放"报告问题"链接，点击才打开浏览器（遵守网络闸门）。

**落点**：`about-v2.component.ts`、新建 `diagnostics.service.ts`、`docs/` 变更日志同步。
**验收**：诊断包人工审查确认无敏感字段；用户可在 3 步内拿到可粘贴的诊断文本。

## 9. 1Password 的弱点 = LocalPass 的机会

| 1Password 的弱点                  | 证据                                                                       | LocalPass 可打的点                                               |
| --------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 订阅制、无永久免费层              | 官方定价与评测一致提及                                                     | "全部功能免费"要能被感知：关于页明确"无订阅、无账号、无到期"     |
| 1P8 取消本地保险库                | 官方与中文评测均指出只能走订阅云同步                                       | 把"数据只在本机"做成可验证事实：网络面板演示、网络闸门日志导出   |
| Chromium 扩展性能与填充可靠性投诉 | 2026-09 社区帖（弹窗慢/崩溃）、2026-03 填充失效帖                          | 用"轻、快、稳定"做对比：首屏 < 300ms、填充规则可解释、失败有原因 |
| 应用体积大                        | 本机 583MB                                                                 | 扩展以 MB 计；安装即用，无需账号                                 |
| 权限面大                          | 扩展申请 `management`/`privacy`/`downloads`/`nativeMessaging`/`<all_urls>` | 权限最小化，并在关于页列出"我们申请了什么、为什么"               |
| 学习曲线                          | 评测反复提到功能多、术语多                                                 | 中文优先 + 少即是多：8 类条目、单库、无团队概念                  |
| 云端信任                          | 闭源服务端                                                                 | 开源 + 可自建备份目标（R2/S3）                                   |

**但要注意**：这些是"营销上的机会"，不是"体验上的优势"。只有在 D1–D5 补齐后，用户才会留下来感受这些差异。

## 10. 本地等价物路线（替代原 anti-roadmap）

原稿把"自动云同步"列为不做，理由是"与只在点立即同步时联网的承诺冲突"。这条已被推翻：**把同步交回用户手动点，正是本报告批评的"服务端琐事下放却没有工具"**。新原则是按"能不能离线成立"分四类处理。

| 类别       | 判断                             | 1Password 能力                                                             | LocalPass 做法                                                                                                 |
| ---------- | -------------------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 能离线成立 | 本地实现，且要做得比对手更细     | 条目历史与回滚、归档、弱密码/重复/超期体检、分享包、桌面应用填充、旅行模式 | 本地版本栈、`archivedAt`、本地规则体检、`.lpshare`、全局检索；旅行模式降级为"安全子集 + 离境清理"              |
| 需要多端   | 用自备桶做加密镜像，不引入服务端 | 自动同步、设备管理、灾难恢复                                               | R2/S3 快照同步：条件写提交点、签名防回滚、冲突保留两份、设备注册表（`docs/LocalPass-离线优先与R2同步设计.md`） |
| 需要多人   | 同级共享，不承诺权限模型         | 共享库、限时链接                                                           | 共享桶（共持密钥）或加密分享包（口令/一次性/过期）；明确"无 per-item ACL"                                      |
| 必须服务端 | **不做**，并在文案里说清         | SSO/SCIM、托管恢复、审计合规、服务端泄露库、计费                           | 无；对应替代是恢复包 + Shamir 分片、本地审计日志、可选 HIBP 前缀查询                                           |

三条边界，写进产品文案而不是藏在脚注：

1. **R2 看不到密码，但看得到"你什么时候改了多少条"**——元数据暴露必须明说。
2. **共享桶没有权限分级**——拿到凭证即读全库，只适合家庭/小团队。
3. **旅行模式不可能"远程移除"**——无服务端就没有远程指令，只能"从不写入 + 离境清理"。

## 12. 附：如何验证这些结论

1. **检索效率**：用 `.playwright-cli` 现有持久化 profile，录屏完成"复制当前站点密码"10 次，统计动作数与中位耗时；改造后同法复测。
2. **搜索命中**：构造含备注、URL、自定义字段的 200 条种子库，跑 20 个真实查询，记录命中率。
3. **迁移保真**：用 1PUX 样本（含 TOTP、附件、自定义字段）导入，逐字段比对；重复导入两次，确认 0 新增。
4. **键盘**：断开鼠标，完成"解锁→搜索→复制密码→编辑→保存→归档"链路。
5. **可访问性**：VoiceOver 走查弹窗列表与 toast；键盘焦点截图存档。
6. **数据安全**：改密码→看历史→恢复；删除→撤销；归档→筛选→取消归档。

**一句话总结**：LocalPass 已经是一个"能用"的离线密码库，但要成为"每天都想用"的产品，缺的不是更多功能，而是**取用速度、可回滚的信任、以及把已有能力送到用户手边的那最后一段路**。
