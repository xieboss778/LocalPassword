# 端到端验证清单

这份清单是「代码能跑」之外的**人工验证**步骤。CI 覆盖不到的两类内容都在这里：
真实浏览器里的 Passkey / 安全密钥行为，以及桌面端打包产物的安装与运行。

> **文案语言说明**：AGY 全端 72 个产品屏及本轮新增/改动文案键均已同步登记至 `en` 与 `zh_CN`（本轮新增键 0 缺键；仓库既有 zh-only 键不在本轮范围），
> 并统一遵循 `GLOSSARY.md` 术语规范（「安全密码」「同步」「导出」「恢复」「保险库」「桶」）。

## 一、扩展（Chrome / Edge，加载已解压）

准备：`chrome://extensions` → 打开开发者模式 → 加载 `localpass-chrome` 目录。

1. **创建保险库**：起始页 → 创建本地保险库 → 页头为「创建保险库」，居中的品牌块下方只有
   邮箱、安全密码与确认三个 32px 输入框，页脚提示「没有「找回密码」」；留空点创建应逐项提示必填。
   填邮箱与安全密码 → 应直接进入空的保险库，并显示居中的空态与「新建条目 / 导入数据 / 从云存储恢复」三个出口；
   建库页只有「创建」与「从云存储恢复」两个入口；扩展首屏没有「创建后导入」开关，导入出口在创建成功后的空库引导中；「从云存储恢复」应能直接打开 R2 恢复向导。
2. **断网可用**：断掉网络（或系统代理指向黑洞），刷新弹出页，仍应能解锁、增删改条目。
3. **付费功能**：新建一个登录条目并填入 TOTP 密钥（`otpauth://` 或 Base32），条目详情应显示验证码；
   点相机图标应弹出二维码；不应出现任何升级提示。
4. **Google 认证器导入**：手机 Google Authenticator → 转移账号 → 导出账号 → 截图 → 设置 → Google 身份验证器 →
   选择截图 → 预览出账号 → 导入 → 保险库中出现对应条目，且 TOTP 可用。
5. **网络闸门**：在扩展的 service worker 控制台执行 `fetch("https://api.local.invalid/sync")`，
   应抛 `NetworkGateBlockedError`；`fetch("https://vault.local.invalid")` 同样被拦截。
   设置 → 网络闸门白名单应只有存储端点（未配置存储时开关为关）；泄露检查应标注「未实现」且没有开关或
   手动查询；页面说明默认拒绝、无隐藏黑名单，不出现固定主机清单、拦截次数或可用的泄露查询入口。
6. **PIN 护栏**：设置 PIN 后连输 5 次错误 PIN —— 应只出现等待提示，**不登出、不清数据**。
7. **登出提示**：设置 → 账户安全 → 登出，确认框应是危险样式并说明会删除本机数据。
8. **Passkey 保存**（需要支持 passkey 的站点，例如 webauthn.me）：
   - 站点发起注册 → 扩展拦截并保存 → 条目详情出现 passkey 信息。
   - 断网后重复注册流程：保存仍应成功（写入走本地，不依赖服务器）。
   - 用该 passkey 登录时，扩展应能取出断言并完成登录。触发验证时，内联「验证中」卡应有页脚「取消」按钮与「30 秒超时」提示，没有 meta 条；正文应说明站点只收到一次签名、私钥不离开本机；点「取消」应中止本次验证。
9. **安全密钥解锁与逐条解绑**：设置 → 安全密钥解锁 → 用支持 PRF 的密钥/平台认证器登记两枚（条件允许时）→
   列表应逐条出现两行（无单独「登记数」计数）→ 对其中一行点单独解绑，该行消失、另一枚仍保留 → 锁定后用保留的密钥解锁应能进入保险库 → 最后点「全部移除」，列表应清空。只有一枚可用认证器时，至少验证单行解绑与「全部移除」。
10. **云备份**：设置 → 云备份 → 填入 R2 端点/桶/令牌 → 测试连接成功 → 保存 →
    配置前已有条目时，状态卡应显示「N 项待上传」（N 为本机新增/修改/删除的条目数，纯本地计算），
    副标题带桶名；改动条目后桶里**不应**自动出现新快照；点「同步」才上传，且桶根出现 `account.json`。
    同步成功后状态卡变为「已同步 · 加密快照」，副标题带桶名与清单代次 `gen #1`；再改 1 条应显示
    「1 项待上传」。再点一次「同步」后 `gen #` 应递增（拉取他端写入时采用对方的代次）。
    点「导出备份」后，`exports/<年-月-日>/` 下应出现一份标准 JSON，桶根同样有 `account.json`。
    存储配置页的 R2 CORS 策略应可一键复制，且包含 `ExposeHeaders: ["ETag"]`。
    冲突验证（两个浏览器 profile 或两台设备，同一条目各自离线修改后再同步）：
    先同步的一台正常上传；后同步的一台拉取后应在状态页出现并排的「本机 / 云端」两侧
    （显示条目名、更新时间与不同的字段标签，且不渲染字段明文），默认选中「两份都留」，
    且「同步」按钮保持禁用、桶里不出现新快照。
    点「提交解决方案」后状态恢复「已同步」，本机同时保留原条目与一份冲突副本；
    重新提交或上传失败后重试不应产生重复副本。另选「只留本机」或「采用云端」时，
    应只保留对应一侧，且解决前看不到任何明文密码出现在日志或诊断中。
11. **离线安全体检**：设置 → 安全体检。新建两条使用同一弱密码的登录、一条未填 TOTP 的登录后进入该页：
    「重复使用密码」应只列出一组、「弱/超期」与「Strong passwords」按真实条目计数，
    列表不重复列出同一条目；断网后重新扫描仍应正常，「去改」应打开对应条目的编辑页。
12. **关于与零敏感诊断**：设置 → 关于，点「Show report」预览与桌面端同模板的诊断；
    报告应包含扩展端/平台/浏览器版本、原生消息权限、聚合计数与同步状态，
    不应出现任何条目名、URL、用户名、密码、动态口令、令牌或密文；点「Copy diagnostics」应提示已复制。
13. **危险清空防呆**：设置 → 数据与安全，未勾选「明白不可撤销」时「清空保险库」应禁用；
    勾选后才启用，点击仍会弹出确认框。该步骤只需验证按钮状态，不要真的清空有数据的库。
14. **生成历史掩码与锁库清空**：生成器生成并复制一个值 → 打开生成历史，条目默认显示 `••••••••••••`；
    点眼睛应只显示该条原值，点复制应得到原值，再点眼睛恢复掩码。关闭再打开弹窗（浏览器未重启）历史仍在；
    锁定后重新解锁，生成历史应为空，且 `chrome.storage.local` 与磁盘文件中都不应出现该明文。
15. **导入去重**：先建一条名称与用户名都已知的登录，再导入包含同名同用户名条目的 JSON；
    预览的「重复跳过」应为 1，列表与主按钮数量都只计其余条目；导入完成后保险库里不应多出重复项。
16. **列表密度与语言跟随**：设置 → 外观与密度 → 选「Ultra compact」，保险库列表行应变为 32px 单行且不显示副标题；
    切回「Compact」恢复 36px 双行。关闭并重开弹窗后选择应保留。同一页面的语言行只读说明「跟随浏览器语言」
    （不是当前语言下拉，也不是切换器）；切换浏览器语言后界面语言应随之变化，且没有可持久化的语言偏好。
17. **动态默认字段**：新建登录 → 点用户名行右侧 ×，该行消失、字段组下方出现「+ Username」胶囊；
    点胶囊恢复该行。填入用户名后再次移除并保存，条目详情不应出现该用户名；重新编辑时字段应重新出现且为空。
18. **枚举与卡有效期**：新建令牌 → 「环境」下拉选「Custom」应变输入框，填自定义值可保存；新建卡片 →
    有效期只有一个 `MM/YY` 输入框，输入 `1230` 应自动显示 `12/30`，保存后详情显示 `12/30`。
19. **导出格式与风险提示**：导出页应有三项格式；所有格式导出前均需输入保险库安全密码校验；
    选择加密 JSON 时另设独立文件密码，选择明文 JSON 或通用 CSV 时隐藏文件密码框、切换为对应风险说明并在导出前弹出二次确认。CSV 文件名应为 `.csv`，且只包含登录与安全笔记。
20. **导入来源**：设置 → 导入应看到 1Password、LocalPass、Bitwarden、Google 认证器、通用 CSV 五行及
    推荐/原生/兼容/2FA/通用徽标；导入一份 Chrome 格式 CSV 应在预览页显示条目数与名称，确认后回到保险库
    并看到该条目。「More sources」应打开完整导入页。
21. **文件夹**：设置 → 我的文件夹，顶部「所有条目」行应显示未删除条目总数，点击回到未筛选保险库；
    新建、改名、删除文件夹后行计数与列表即时更新，删除文件夹不删除其中条目。
22. **剪贴板与密码自动收回**：设置 → 安全设置，「清空剪贴板」行应显示当前延迟，新装默认「30 秒」；
    「Auto-hide revealed passwords」默认开启。打开一条登录详情点眼睛显示密码，30 秒后应自动恢复掩码；
    关闭该开关并重开弹窗后开关仍为关，再次显示密码 30 秒后应保持可见。
    复制一个密码后 30 秒内不复制其他内容，剪贴板应被清空。再把「清空剪贴板」改为「10 秒」并复制一个生成器密码，
    回执应显示 10 秒并在到时清空；改为「永不清空」后复制，回执仍显示但不自动清空，剪贴板保留该值。
23. **桌面触控 ID 代理桥接**：设置 → 安全设置，「指纹解锁」行应显示真实桥接状态：未授权原生消息时
    点整行可直接发起原生消息权限请求（弹窗自动弹出独立窗口并重载扩展），桌面端未运行时提示
    「桌面端未运行」，桌面端未开通时提示「请先在桌面端开启触控 ID 解锁」，绝不在本页假装打开开关。
    授权且桌面端就绪后回到本行，开关应可开启；关闭后状态回到未开启。开启后锁定保险库，解锁页应出现
    「使用生物识别解锁」按钮，点击由 `com.localpass.desktop` 弹出 Mac Touch ID 确认并完成解锁。

## 二、桌面端

准备：Windows 安装包（CI 产物）或 macOS dmg。

1. **安装**：Windows 上 SmartScreen 选择「仍要运行」；macOS 右键 → 打开。
2. **创建/解锁**：桌面建库页有「创建后导入」开关（默认关），开启后创建成功进入导入（扩展首屏没有该开关，创建后由空库引导提供导入出口）；桌面端用系统生物识别（Windows Hello / Touch ID）解锁，未配置时退回主密码。
3. **跨端同步**：先在桌面端建库并配置桶、点「同步」上传 `account.json` 与第一份快照；扩展全新安装后从
   「从云存储恢复」填入同一端点/桶/令牌与桌面端主密码。恢复出的账号应与桌面端是同一个 `userId`
   （桶根的 `account.json` 里写着它），之后两端点「同步」后改动的条目应互相可见。
4. **无后台上传**：把窗口收进托盘放置 10 分钟，桶里不应出现新对象；只有回设置页点「同步」或「导出备份」才应上传。
5. **滚动备份**：退出应用，检查 `<userData>/data.json.bak` 存在且非空。
6. **原生消息**：浏览器与桌面端同时运行，扩展的「用桌面应用解锁」链路应可用（主机名 `com.localpass.desktop`）。
7. **离线安全体检**：左侧「安全体检」应显示真实的待处理数角标与统计卡；点「Fix」应回到保险库并展开该条目的编辑抽屉
   （`/vault?cipherId=...&edit=1`）；断网后结果不变，且页面不发起任何联网查询，也没有手动 HIBP / 泄露查询入口。
8. **菜单栏托盘面板**：在设置中开启「关闭窗口后继续运行」，点亮菜单栏图标应弹出 304×380 面板；搜索并点复制按钮应复制密码，
   「Generate & copy」应复制 20 位本地生成密码；点锁定后面板立即收起，再次点托盘应回到主窗口解锁页。
9. **版本历史与恢复**：编辑一条任意类型条目并修改字段（登录换密码、银行卡换卡号或身份换地址）→ 详情页头的时钟图标
   打开历史抽屉，应显示当前版本与旧版本；每条旧版本列出「与当前不同的字段」标签（只显示标签，不显示字段值）。
   登录旧版可点眼睛切换掩码、点复制得到旧密码；点「恢复」应把该版本写回当前条目，原当前版本进入历史。
   连续修改 11 次后只保留最近 10 个旧版本；保存时未改动任何字段不应新增版本；彻底删除条目后其版本栈一并清除；
   断网后同样可用。
10. **删除撤销**：删除一条条目 → 确认后底部出现「已移到回收站」与「撤销」；5 秒内点撤销，条目应回到列表，
    超过 5 秒 Toast 消失、条目留在回收站。确认框里的「改用归档」应把条目移入归档而不是回收站。
11. **关于与离线诊断**：设置 → 关于，应看到 GPL-3.0、更新日志与源码入口，以及三条已知限制
    （手动同步、无逐字段合并、版本历史保留 10 个旧版本，不是 5 个）；
    点「Show report」预览的诊断只含版本、平台、语言、主题、条目/文件夹/回收站聚合数与同步状态，
    不应出现任何条目名、URL、用户名、密码、动态口令、令牌或密文；点「Copy diagnostics」应提示已复制，剪贴板内容与预览一致。断网后同样可用。
12. **网络闸门与 CORS**：管理 → 网络闸门白名单应只有存储端点（未配置存储时存储开关为关）；泄露检查应标注
    「未实现」且没有开关或手动查询；页面说明默认拒绝，不出现固定主机清单或拦截次数；云备份 → 存储配置右侧的 R2 CORS 策略可复制，
    内容包含 `GET/PUT/HEAD/DELETE` 与 `ExposeHeaders: ["ETag"]`。
13. **数据安全文案与危险清空防呆**：管理 → 数据与安全，统计卡应显示「系统保护」（OS-protected）、云备份（已配置 R2 时显示 `R2`，否则 `—`）与 0 个「官方服务器副本」（Vendor server copies）；
    目录行说明路径由操作系统管理、随平台变化，不出现 `0600` 权限或 macOS `~/Library/Application Support/LocalPass`
    的硬编码断言。未勾选确认时「清空保险库」应禁用；勾选后才启用，点击仍会弹出二次确认；
    旁边的「Export backup first」应直达导出页。该步骤不要真的清空有数据的库。
14. **生成历史掩码与锁库清空**：工具 → 生成器生成并复制一个值 → 生成历史条目默认显示掩码；
    眼睛按钮逐条显示/隐藏，复制按钮得到原值。锁定再解锁后历史应为空；连续复制 21 个不同值最多保留 20 条。
    应用数据目录中不应出现该生成值的明文（历史仅驻留内存）。
15. **导入去重**：用桌面端导出 JSON，再修改其中一个条目的密码后重新导入；预览应把该条计为重复并跳过，
    主按钮只统计其余条目，导入后不新增重复项，文件夹关系仍正确。
16. **列表密度**：设置 → 外观 → 选「Ultra compact」，保险库列表行应变为 30px 单行；
    点列表右上角的密度按钮也应即时切换并写入同一设置；重开应用后选择应保留。
17. **动态默认字段**：新建登录 → 移除用户名并在字段组下方点「+ Username」加回；
    填入用户名后再次移除并保存，详情不应显示该用户名，重新编辑时该行应重新出现且为空。
18. **枚举与卡有效期**：令牌类型「环境」可在下拉预设与「自定义」输入间切换；卡片类型有效期仅为
    一个 `MM/YY` 单框，输入 `1230` 自动变 `12/30`，保存后详情与再次编辑均保持该格式。
19. **应用内快捷键映射**：设置 → Shortcuts 应列出 6 行（`⌘K / /`、`↑↓ · ↵`、`⌘C / ⇧⌘C`、
    `⌘N · ⌘E`、`Delete / ⌘⌫`、`⌘L`）。删除「Open quick search」后回保险库：搜索框与底栏的
    `⌘K` 提示应消失，按 `⌘K` 或 `/` 均不再打开快速检索浮窗；删除「Lock the vault」后按 `⌘L`
    不应锁库。点「Reset defaults」恢复 6 行后，`⌘K` 应恢复打开快速检索；重开应用删除状态仍保留。
20. **Google 认证器导入**：工具 → 导入 → Google 认证器；粘贴 `otpauth-migration://` 链接或
    选择二维码截图，预览应显示「服务 · 账号」，不展示密钥原文；导入后回到保险库应出现对应验证码条目。
    再次导入同一密钥时，预览应标记为已存在并默认跳过；扩展弹窗走同一流程。
21. **导出格式与风险提示**：导出页应有三项格式；选择明文 JSON 或通用 CSV 时密码框隐藏，
    警告文案切换为对应风险说明，导出前弹出二次确认。CSV 文件名应为 `.csv`，且只包含登录与安全笔记。

## 三、网页内联菜单

准备：在已保存登录（含 TOTP 密钥）的站点聚焦账号或验证码输入框。

1. **验证码填充胶囊**：聚焦一次性验证码输入框 → 内联菜单列出验证码 → 填充后菜单应收窄为
   30px 页头 + 38px 绿色确认条，显示「剩余 N 秒」且不再展示验证码原文；
   点确认条右侧按钮应回到验证码列表，页面里已填入的值不受影响。
2. **登录建议菜单底栏**：在登录页聚焦用户名输入框 → 菜单宽度应跟随聚焦输入框（AGY 原型中
   示例站点栏宽为 312px）、28px 单行页头、36px 账户行，账户副标题写明是否含验证码但右侧不
   出现动态码；底栏应有「生成密码」与「在扩展中搜全部」。「生成密码」应就地把菜单切到强密码
   生成视图（可填入、可换一个）；重新打开菜单点「在扩展中搜全部」应关闭内联菜单并弹出扩展
   保险库列表浮窗，在浮窗搜索框中能检索到其他站点的条目。
3. **银行卡与身份菜单**：在结账页聚焦卡号输入框 → 菜单宽度应跟随聚焦输入框（AGY 原型示例
   站点为 312px）、28px 页头（`LocalPass · Cards`）、36px 卡片行，卡号只显示 `•••• 尾号`
   与 `09/29` 有效期，收藏项应置顶并带 `Favorite` 徽标；行右侧常驻 `Fill` 胶囊，点行应填入
   卡号与有效期并关闭菜单。聚焦收件地址输入框 → 页头应为
   `LocalPass · Identity & address`，副标题为真实保存的地址，点行应填入姓名与地址并关闭菜单。
   底部提示条应说明完整卡号不显示，并显示 `↑↓ ↵ esc`。卡片与身份混合的列表（例如账户创建
   场景）应保留旧列表的查看入口。
4. **填充回执与撤销**：完成登录、银行卡或身份填充后，页面右下角应出现 320px 回执卡
   （登录显示 `Filled credentials for 条目名`，银行卡显示 `Filled card ending 尾号`，身份显示
   `Filled contact and address`）；点「撤销」应清空该次填充写入的全部字段（用户名、密码、验证码或
   卡号/地址）且不触碰用户原有内容，卡片切到撤销态；再点「重新填充」应恢复填充。回执 8 秒后自动消失，
   期间切换页面不应残留；回执内不得出现账号、密码、完整卡号或身份字段值。
5. **改密保存条与多账户精确选择**：同一域名下保存两条密码与页面当前密码一致的登录，另存一条
   密码不同的登录。在改密页输入当前密码与新密码并提交 → 右上角出现 320px 选择器，**只**列出
   密码匹配的两条（不一致的那条不出现），末行为「Save as new entry #4」（该域名已有
   3 条，编号按全部条目数 + 1，含不匹配的那条）；选中另一账户后主按钮
   应变为「Update … password」，账户行副标题应显示真实的「条目名 · 上次使用于 N 分钟前 · vN」；
   提交后确认条应为 316px 绿色成功卡「登录已更新 / 条目名 · 用户名 / 已加密存入「文件夹」·
   2 分钟内自动收起」，带「补充 2FA / 编辑条目」与「完成」两个按钮；点前者应打开该条目的
   编辑弹窗。点「Save as new entry #4」后
   主按钮变为「Create entry #4」，提交后确认条显示「登录已保存」，保险库新增独立条目且原有条目
   密码不变。换一个新标签页使只有一条条目与当前密码匹配 → 应直接显示 294px 单条卡，说明行应写
   「保留 vN 到历史版本」，主按钮为「Update entry (vN+1)」，点「Switch / save as new」才展开
   320px 选择器；卡内文案不得出现「已更新」用于新建结果。用户名相同但密码不同的条目在任何情况下都
   不应出现在选择器里；再在同一域名下只保存密码不同的登录，提交当前密码 → 选择器仍出现，但只保留
   「Save as new entry #N」与「Ignore」，没有可更新条目。
6. **首次保存卡片与忽略提示**：在未保存过登录的站点用新账号登录 → 右上角出现 320px 卡：
   页头「要保存 <站点> 的登录吗？」，首行为用户名，次行为「首次登录 <站点> · 选择归属文件夹后
   写入本机」，下方是含「无文件夹」的文件夹下拉。选一个文件夹后主按钮文字应实时变为
   「保存到「文件夹」」→ 点它出现 316px 绿色确认卡「已安全保存到 LocalPass / 条目名 · 用户名 /
   已加密存入「文件夹」 · 2 分钟内自动收起」，保险库中该条目应落在所选文件夹（文件夹计数 +1）。
   再到另一未保存站点登录后点「从不提示此站」→ 卡片关闭、保险库不新增条目；在同一站点再次
   提交登录，不应再弹出保存卡。
7. **改密强密码建议**：在改密页聚焦「新密码」输入框 → 内联菜单应为 `LocalPass · 强密码建议` 页头、
   分色等宽密码预览（长度与生成设置一致）、「N 位强密码 · 填入并打开保存确认条」说明（N 为实际生成
   长度，不是固定 20）、蓝色 `填入` 按钮，底栏为 `换一个` 与 `只在本机生成`。点 `填入` → 新密码框被
   写入该密码、菜单收起，首次保存卡自动出现（先等约 `300ms`，`1.5s` 兜底），而不是页面提交后才出现；
   点「保存」→ 316px 绿色确认卡。点底栏 `换一个` 应换一条密码且不写入页面。
8. **弱/重用密码网页改密提醒**：在本机保险库保存两条共用同一弱密码的登录（如 `dup-pass-123`
   分属两个站点），再保存一条密码唯一但过短的登录。用共用密码的账号在第一个站点登录 → 右上
   角出现 326px 琥珀卡：页头「此账号使用了重复或偏弱密码」、红色胶囊「重复 2 处」、
   「条目名 · 用户名」与「多个登录处重复使用同一密码。」，以及「更改密码 / 稍后」两个按钮。
   点「更改密码」→ 打开该条目的编辑弹窗、通知条关闭；换新标签页用弱密码账号登录 → 同一张卡
   显示「弱密码」与「密码过短或过于简单。」；点「稍后」仅关闭通知条。全程不应发起任何网络
   请求，也不应在通知条以外记录明文密码。
9. **内联就地解锁**：锁定保险库后，在已保存登录的站点聚焦用户名输入框 → 内联菜单出现紧凑
   锁定卡：页头 `LocalPass · Locked`、说明行「Unlock to fill <域名>」、主密码输入框与
   `Unlock account` 按钮，底部提示「This also unlocks the extension popup.」；未连接桌面端时
   不应出现生物识别按钮。先输入错误主密码回车 → 菜单仍保持锁定并显示
   「Could not unlock. Try again.」，密码框内容应立即清空；再输入正确主密码回车 → 菜单就地
   刷新为该站点的登录列表，页面 DOM、控制台与扩展日志中都不应出现密码明文；随后新开扩展
   弹窗应直接进入保险库，而不是解锁页。

## 四、CI 覆盖不到的已知限制

- **macOS 打包**：`macos-15` runner 可能长时间排队，但 dmg 是交付物，
  该 job 已改为**必过**（不再是 `continue-on-error`）；构建失败会让流水线变红。
- **Passkey / PRF 行为**：依赖真实认证器与浏览器实现，CI 只能做类型与单测，行为需按上面第 8、9 条人工确认。
- **全量单测**：当前约 1280 suites / 26245 tests，只在手动触发 `workflow_dispatch` 时全量执行；
  推送门禁跑的是改动范围（`libs/local-vault` / `importer` / `key-management-ui` / `common/src/dirt`）。
- **Google 认证器导入的 HOTP 限制**：桌面与扩展共用同一导入组件，支持 otpauth-migration URI
  与二维码截图；HOTP 是计数器型条目，当前只能报告数量、不能写入，预览也不会展示密钥原文。
- **桌面设置与密钥轮换边界**：桌面端外观页语言切换（中/英）、托盘常驻、剪贴板自动清除与密码 30 秒自动收回开关均已可用；
  桌面端安全密钥卡片已如实标注「仅扩展可用」。**本地更换安全密码**（本机重新包装加密密钥）属于密钥与加密敏感改动，当前保持诚实提示并待仓库所有者评审后实施，不调用已禁用的远端密码修改接口。
- **AGY 73 屏走查基线**：[屏对照表](./LocalPass-屏对照表.md) 已把 72 个产品屏标为对齐（`link-sandbox` 为原型演示页）。每轮 UI 改动仍需人工确认：桌面第二栏与扩展列表不展示 TOTP 动态码、桌面登录详情不展示 Google 验证器绑定二维码、详情不留冗余「复制主要值」按钮、卡片有效期使用 `MM/YY` 单框输入，以及设置页应用内快捷键删除与重置（无系统全局热键）。
- **Touch ID 最终确认**：桌面 `com.localpass.desktop` 桥接与系统指纹弹窗无法在自动化浏览器中伪造；扩展内联解锁与扩展解锁页的生物识别按钮只在桌面桥上报 `Available` 时出现，真机确认需在装有桌面 App 的 Mac 上按下第 1 节第 23 条人工验证。
- **替换扩展构建后必须重新加载**：用新产物覆盖 `apps/browser/build` 后，旧的 MV3 service worker
  可能仍在运行，弹出页按钮会无响应。到 `chrome://extensions` 点「重新加载」，
  或关闭浏览器重开；只重启扩展进程不够。
- **同步没有后台任务**：关闭弹窗可能中断正在进行的同步；重新打开后手动重试。
  桶里不会因本地改动自动出现新对象。
