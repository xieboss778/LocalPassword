# 端到端验证清单

这份清单是「代码能跑」之外的**人工验证**步骤。CI 覆盖不到的两类内容都在这里：
真实浏览器里的 Passkey / 安全密钥行为，以及桌面端打包产物的安装与运行。

## 一、扩展（Chrome / Edge，加载已解压）

准备：`chrome://extensions` → 打开开发者模式 → 加载 `localpass-chrome` 目录。

1. **创建保险库**：起始页 → 创建本地保险库 → 填邮箱与主密码 → 应直接进入空的保险库。
2. **断网可用**：断掉网络（或系统代理指向黑洞），刷新弹出页，仍应能解锁、增删改条目。
3. **付费功能**：新建一个登录条目并填入 TOTP 密钥（`otpauth://` 或 Base32），条目详情应显示验证码；
   点相机图标应弹出二维码；不应出现任何升级提示。
4. **Google 认证器导入**：手机 Google Authenticator → 转移账号 → 导出账号 → 截图 → 设置 → Google 身份验证器 →
   选择截图 → 预览出账号 → 导入 → 保险库中出现对应条目，且 TOTP 可用。
5. **网络闸门**：在扩展的 service worker 控制台执行 `fetch("https://api.local.invalid/sync")`，
   应抛 `NetworkGateBlockedError`；`fetch("https://vault.local.invalid")` 同样被拦截。
6. **PIN 护栏**：设置 PIN 后连输 5 次错误 PIN —— 应只出现等待提示，**不登出、不清数据**。
7. **登出提示**：设置 → 账户安全 → 登出，确认框应是危险样式并说明会删除本机数据。
8. **Passkey 保存**（需要支持 passkey 的站点，例如 webauthn.me）：
   - 站点发起注册 → 扩展拦截并保存 → 条目详情出现 passkey 信息。
   - 断网后重复注册流程：保存仍应成功（写入走本地，不依赖服务器）。
   - 用该 passkey 登录时，扩展应能取出断言并完成登录。
9. **安全密钥解锁**：设置 → 安全密钥解锁 → 登记（需要支持 PRF 的密钥/平台认证器）→ 登记数量变为 1 →
   锁定后用安全密钥解锁应能进入保险库。
10. **云备份**：设置 → 云备份 → 填入 R2 端点/桶/令牌 → 测试连接成功 → 保存 →
    改动条目后桶里**不应**自动出现新快照；点「同步」才上传，且桶根出现 `account.json`。
    点「导出备份」后，`exports/<年-月-日>/` 下应出现一份标准 JSON，桶根同样有 `account.json`。

## 二、桌面端

准备：Windows 安装包（CI 产物）或 macOS dmg。

1. **安装**：Windows 上 SmartScreen 选择「仍要运行」；macOS 右键 → 打开。
2. **创建/解锁**：与扩展一致；桌面端用系统生物识别（Windows Hello / Touch ID）解锁，未配置时退回主密码。
3. **跨端同步**：先在桌面端建库并配置桶、点「同步」上传 `account.json` 与第一份快照；扩展全新安装后从
   「从云存储恢复」填入同一端点/桶/令牌与桌面端主密码。恢复出的账号应与桌面端是同一个 `userId`
   （桶根的 `account.json` 里写着它），之后两端点「同步」后改动的条目应互相可见。
4. **无后台上传**：把窗口收进托盘放置 10 分钟，桶里不应出现新对象；只有回设置页点「同步」或「导出备份」才应上传。
5. **滚动备份**：退出应用，检查 `<userData>/data.json.bak` 存在且非空。
6. **原生消息**：浏览器与桌面端同时运行，扩展的「用桌面应用解锁」链路应可用（主机名 `com.localpass.desktop`）。

## 三、CI 覆盖不到的已知限制

- **macOS 打包**：`macos-15` runner 可能长时间排队，但 dmg 是交付物，
  该 job 已改为**必过**（不再是 `continue-on-error`）；构建失败会让流水线变红。
- **Passkey / PRF 行为**：依赖真实认证器与浏览器实现，CI 只能做类型与单测，行为需按上面第 8、9 条人工确认。
- **全量单测**：当前约 1280 suites / 26245 tests，只在手动触发 `workflow_dispatch` 时全量执行；
  推送门禁跑的是改动范围（`libs/local-vault` / `importer` / `key-management-ui` / `common/src/dirt`）。
- **重复导入不去重**：导入预览能显示“重复条目 / 无法识别”，但导入服务不跳过已有条目，
  重复数恒为 0（见 [屏对照表](./LocalPass-屏对照表.md)「已知差异」第 1 条）。这是已知功能缺口，不是预览 bug。
- **桌面设置缺口**：已登记安全密钥的“管理”入口、外观页语言切换入口尚未实现；
  安全密码修改已可用。
- **AGY 73 屏目标规范演进验证**：待 [屏对照表](./LocalPass-屏对照表.md) 中各端界面逐步切换为 `design-system/agy/`（AGY Compact v4）后，新增人工走查：桌面第二栏与扩展列表不展示 TOTP 动态码、桌面登录详情不展示 Google 验证器绑定二维码、详情不留冗余「复制主要值」按钮、卡片有效期使用 `MM/YY` 单框输入，以及设置页应用内快捷键删除与重置（无系统全局热键）。
- **替换扩展构建后必须重新加载**：用新产物覆盖 `apps/browser/build` 后，旧的 MV3 service worker
  可能仍在运行，弹出页按钮会无响应。到 `chrome://extensions` 点「重新加载」，
  或关闭浏览器重开；只重启扩展进程不够。
- **同步没有后台任务**：关闭弹窗可能中断正在进行的同步；重新打开后手动重试。
  桶里不会因本地改动自动出现新对象。
